01 / Foundations

The base: color, type, grid and light.

Everything a slide uses comes from here. Slides never use a loose hex value — only semantic tokens.

Principles

Five rules that settle the cases this documentation doesn't cover.

One idea per slideThe title states the conclusion; everything else proves it.
Type before effectsIf the slide doesn't work without the gradient, it doesn't work.
Blue is the pointOnly the most important number or word gets blue.
Contained lightA gradient is an object (strip, panel, column), never wallpaper.
Honest numbersZero-based scales, stated sources, illustrative data flagged.

Data visualization

Write the chart as data (data-chart='{…}') and the script draws the SVG with the slide's tokens. Bars always start at zero, labels are direct, only the main point is blue.

Line · area · time series

type: "line"
Options
area, kind: bench|secondary, ann (max 2), ticks, fmt.
Question
What changed, by how much, over what period, compared to what?

Bars and horizontal bars

type: "bars" · "hbars"
Use
Comparison by category, ranking, benchmark. Horizontal when labels are long.
Rule
Zero-based axis; the same yMax across side-by-side charts.

Composition · 100% bar and donut

type: "stack" · "donut"
Use
Parts of a whole. Prefer the 100% bar; donut only with ≤ 4 slices and the point written in the center.
Rule
2–4px gap between slices; a direct label on each.

Before × after

type: "pairs"
Use
The same metrics over two periods of equal length. Each row has its own scale, so every value is labeled.
Rule
State whether “lower is better”.

Funnel

type: "funnel"
Honesty
Each stage is drawn as a % of the previous stage, because volumes span orders of magnitude. The absolute volume appears as text.

04 / Guidelines

How to keep everything consistent.

For designers and for AI agents building decks with this system.

Brand consistency

  • Primary Blue #3746CC is the only accent blue. #1F6FEB (website) never goes into a deck.
  • Cyan and lavender: gradients and data series only.
  • Rhythm: ~80% light slides; dark for cover, dividers, hero metric and closing.
  • Never two consecutive dark slides with the same light focus.

Data presentation

  • Title = conclusion (“CPI fell 40%…”), never the topic (“Campaign results”).
  • Bars start at zero. Side-by-side charts share the same scale.
  • One point in blue; everything else neutral.
  • Every number has a source in the footer. Unverified data says “Illustrative data” there, once.
  • No dual axes, no 3D, no decorative arrows.

Content density

  • Title ≤ 10 words; it carries the point, so no subtitle under it.
  • Max 3 blocks per slide; max ~15 words besides the title.
  • Labels: 1–3 words, only when a chart needs a name. No label repeats the title.
  • Header = section eyebrow only. Footer = logo · source · page. No context lines.
  • Details live in the speaker notes, not on the slide.
  • If it doesn't fit at 24px, cut words or split the slide. Never shrink.

Accessibility

  • Text: minimum contrast 4.5:1 (the lightest gray is #6A7489).
  • No text over the area of greatest variation in a gradient.
  • Change always shown with arrow + sign + text, never color alone.
  • Minimum type size on a slide: 24px on the 1920 canvas.

Imagery

  • Real client creatives > generic illustration. No decorative stock imagery.
  • App screenshots always inside .phone, undistorted.
  • Advertiser colors belong to the advertiser: they never join the palette.
  • Concept mockups say “Concept mockup” in the footer.

Co-branding

  • Lockup: Simula · hairline · partner, aligned by optical height.
  • Partner color only inside the partner logo (e.g. Livewire green).
  • On dark, the partner icon uses a single-color white version.

Export

  • Fixed 1920 × 1080 canvas; deck-stage scales it to the screen.
  • PDF: Print → Save as PDF (one slide per page).
  • Videos become their first frame in PDF: set a poster.
  • Fonts: Geist via Google Fonts; Inter as fallback.

Open brand items

  • Official reversed logo file (currently derived in CSS).
  • Map re-exported in #3746CC.
  • Confirmed time-spent benchmarks for demo slide 03.

For AI agents: build protocol

  1. Link simula-ds.css, then the deck HTML, then simula-charts.js, and deck-stage.js last.
  2. Each slide is a <section class="slide"> with .s-head, .s-body and .s-foot. Dark: add dark + bg-midnight or a .curtain.
  3. Start by copying the closest template from Simula Templates.html; don't invent new layouts unless needed.
  4. Use only tokens (var(--text-primary)…) and type classes (.t-h-xl…). Loose hex values only for partner colors.
  5. Write the title as a conclusion. One blue point per slide.
  6. Never invent metrics. No data → a labeled .ph or [XX]. Example data → .flag “Illustrative data”.
  7. Charts via data-chart, with a shared yMax across neighboring charts.
  8. Before delivering: check grid alignment, contrast, text overflow, and that every slide reads in 5 seconds.
